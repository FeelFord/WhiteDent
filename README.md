# WhiteDent — демонстрационная версия

Демонстрационный многостраничный сайт стоматологии WhiteDent, Караганда, Казахстан. Next.js App Router, React, TypeScript, Tailwind CSS 4, Motion, Lucide, Playwright. Рабочая ветка — `main`.

## Запуск

Требуется Node.js 22–24 (рекомендуется 24) и npm. Используйте существующий checkout `/workspace/WhiteDent`: дополнительный Git worktree не нужен.

```bash
cd /workspace/WhiteDent
npm ci
npm run dev
```

Dev-сервер слушает порт 3000. Откройте его в браузере на своей машине через доступное перенаправление порта. В onboarding-интерфейсе предпросмотр localhost не предоставляется; для просмотра вне облака потребуется локальная копия файлов или поддерживаемое окружением перенаправление порта. Публичный деплой не требуется.

Для локальной копии клонируйте `https://github.com/FeelFord/WhiteDent.git` и используйте каталог проекта вместо `/workspace/WhiteDent`. Исходники хранятся в `main`.

## GitHub Pages

Подготовлена статическая версия для стандартного адреса `https://feelford.github.io/WhiteDent/`. Готовые файлы публикуются в отдельной ветке `gh-pages`; собственный домен не подключается.

```bash
npm ci
npm run build:pages
npm run test:pages
npm run preview:pages
```

Локальный статический просмотр слушает порт 3200 и путь `/WhiteDent/`. `npm run start` относится к обычной Next.js-сборке; после статического экспорта для неё сначала снова выполните `npm run build`.

Публикация проверенного экспорта: сохраните исходные изменения в коммит, затем выполните `npm run deploy:pages`. Команда отправляет только содержимое `out/` в `gh-pages`, без force push, изменения основной ветки и собственного домена. Она проверяет noindex всех HTML и контрольную сумму оригинального логотипа. Исходники из main отправляются отдельно обычным Git push. Подробности и включение Pages: `docs/github-pages.md`.

## Production и проверки

```bash
npm run build
npm run typecheck
npm run test:e2e
npm run start
```

Сначала выполните build. E2E самостоятельно запускает production-сервер на порту 3100, который должен быть свободен. Для браузера автоматически используется `/usr/bin/chromium`, если он есть. На другой машине установите Playwright Chromium через `npx playwright install chromium` или укажите `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

E2E-проверки: ширины 320/375/768/1024/1440 на всех страницах, отсутствие переполнения и ошибок браузера, сквозная навигация, мобильное меню и фокус, клавиатурный FAQ, фильтрация, детали услуг и врачей, локальная валидация формы, отсутствие отправки и сохранения полей, деморежим, robots, sitemap, карта, skip-link, reduced motion и 404. Это Chromium-проверки; Safari, Firefox и реальные устройства не проверялись.

В общий набор также включён axe-аудит 12 страниц и интерактивных состояний (мобильное меню, ошибки формы, фильтр, FAQ), а также проверка уникальности SEO/Open Graph/Twitter-метаданных. Отдельный запуск: `npm run test:quality`. JSON с найденными нарушениями и случаями для ручной проверки сохраняется во вложениях Playwright в `test-results/`. Автоматический аудит не подтверждает полное соответствие WCAG.

## Структура

```text
src/
  app/                     layout, главная, CSS, robots, sitemap, 404
    services/[slug]/       каталог направлений и детальные страницы
    doctors/[slug]/        раздел врачей и демонстрационный профиль
    about/                 о клинике
    contacts/              контакты, ссылка на 2ГИС, демо-форма
    privacy/               черновик политики
  components/
    layout/                Header и Footer
    sections/              Hero, Approach, Services, Team, Faq, Contacts
    services/              фильтруемый каталог
    forms/                 форма без отправки
    ui/                    Reveal, PageHeading, ContentNotice
  config/navigation.ts     сквозная навигация
  config/site.ts           префикс статических ресурсов
  data/                    clinic, services, doctors, faq
  types/content.ts         статусы и типы контента
  lib/validation.ts        валидация демонстрационной формы
  lib/seo.ts               единые метаданные демоверсии
tests/e2e/                 главная, страницы и сценарии
tests/pages/               проверки статической версии с /WhiteDent/
scripts/                   сборка, просмотр и публикация Pages
docs/                      дизайн-система и реестр проверки контента
```

## Ограничения этапа

- Оригинальный WD-логотип находится в `public/brand/whitedent-logo.png` (300 × 300). Файл из репозитория перемещён без изменения байтов, подключён в Header, Footer и как favicon. Цвета, фон, буквы и пропорции сохранены. См. `docs/logo-integration.md`.
- Адрес, телефон, WhatsApp, график, Instagram и услуги требуют подтверждения. Номера хранятся в конфигурации, но не подключены к рабочим ссылкам.
- Врачи не выдуманы: `doctors.ts` содержит один явно демонстрационный профиль без ФИО, стажа и образования. CSS-композиции — декоративная графика, не фото клиники.
- Запись отключена. Форма на `/contacts` проверяет только локальные значения и не отправляет их; используйте вымышленные данные. Без JavaScript поля и кнопка отключены.
- Все HTML содержат noindex. В серверном режиме дополнительно установлен X-Robots-Tag. На GitHub Pages основной механизм — HTML noindex; robots.txt в подпапке проекта не управляет всем доменом github.io.
- Sitemap в деморежиме пустой. Canonical не задан без утверждённого домена. Privacy — юридически не согласованный черновик. Реальная отправка требует отдельного согласования.
- Демонстрационная публикация разрешена пользователем. Официальный запуск, подключение своего домена и изменение white-dent.kz не разрешены.

См. `docs/content-verification.md`, `docs/design-system.md`, `docs/stage-3-validation.md` и `docs/launch-checklist.md`.

# WhiteDent: локальная передача проекта

## Состав

Подготовлены исходники Next.js, TypeScript, Tailwind CSS, Motion и Lucide, все страницы демонстрации, конфигурации данных, оригинальный WD-логотип, lockfile, Playwright/axe-проверки и документация. Работа находится в `main` репозитория `FeelFord/WhiteDent`.

Создаётся локальный коммит с сообщением `feat: build WhiteDent demo with original WD branding`. Посмотреть его полный состав можно командой `git show --stat HEAD`, а изменения — `git show HEAD`. Этот коммит не отправляется автоматически.

Исходный `dfcc5e.png` из пользовательского коммита `a53f778` перемещён в `public/brand/whitedent-logo.png` без изменения байтов. Git определяет его как переименование с совпадением 100%.

## Проверки перед передачей

- Последняя production-сборка и TypeScript прошли после интеграции оригинального логотипа.
- Последний полный прогон — 47/47 Playwright-проверок, 0 пропущенных; 56.6 с.
- PNG доступен на диске и по HTTP, контрольная сумма совпадает с оригиналом.
- После этих проверок менялась только документация о передаче; приложение не менялось.
- Архив создаётся из Git HEAD и проверяется на целостность, наличие ключевых файлов и сохранность логотипа.

Подробные отчёты: `logo-integration.md`, `stage-3-validation.md`. Lighthouse-оценки относятся к версии до интеграции PNG, это отмечено в отчётах.

## Архив

Путь текущего сеанса: `/workspace/exports/WhiteDent-demo-source.zip`. Архив содержит исходники из локального коммита; в нём нет Git-метаданных, node_modules, сборки .next, npm-кэша и runtime-процессов. Файл SHA-256 расположен рядом. Дополнительный архив `WhiteDent-demo-preview.zip` содержит актуальные скриншоты с логотипом и отчёт интеграции.

После распаковки на машине с Node.js 24:

```bash
npm ci
npm run dev
```

Для production-проверки:

```bash
npm run build
npm run typecheck
npm run test:e2e
npm run start
```

Если Chromium отсутствует, выполните `npx playwright install chromium` перед E2E. Дополнительные условия — в README.

## Дальнейший шаг

Push в GitHub и публикация Vercel требуют отдельного явного разрешения пользователя. Локальный коммит и архив не означают, что сайт опубликован или что код уже находится на GitHub.

Даже после разрешённой публикации демонстрация должна сохранять noindex, отключённые неподтверждённые контакты и локальный режим формы. Официальный запуск требует проверки содержания и реальных процессов по `launch-checklist.md`.
